# Подключение остальных проектов

Мониторинг развёрнут на первом проекте. Всего проектов четыре, у каждого своя
панель Remnawave и свои ноды. Здесь — как подключить остальные.

## Развилка

**Один хаб на все проекты (рекомендуется).** Один бот, один чат, одна история,
одна точка, куда смотреть утром. Проекты различаются лейблом `project` у каждой
метрики. Ресурсов нужно чуть больше, чем сейчас, — и это всё.

**Четыре отдельные установки.** Полная изоляция, но вчетверо больше всего:
четыре хаба, четыре бота, четыре сторожа, четыре набора обновлений. При падении
общего для всех хостера вы получите четыре независимых потока сообщений об одном
и том же событии.

Выбирайте первое, если проекты ваши и смотрите на них вы же. Второе оправдано
только если проекты надо разделить юридически или отдать разным командам.

Дальше — по первому пути.

## Что меняется

### 1. Приватная сеть

Каждая панель становится пиром WireGuard. Адреса по одному на проект, чтобы не
путаться: `.2` — панель проекта 1, `.4` — проекта 2, `.6` — проекта 3, `.8` — проекта 4.
Нечётные остаются под служебные машины.

```bash
./scripts/wg-add-peer.sh panel-p2 4
```

Конфиг положить на сервер панели, поднять `wg-quick@wg0`, проверить `ping 10.77.0.1`.

### 2. Пробник в каждой локации

На сервере каждой панели поднимается свой blackbox — так проверки доступности идут
из той же страны, где сидят клиенты этого проекта. Порт тот же, адрес свой:

```bash
PROBER_PRIVATE_IP=10.77.0.4 docker compose up -d
```

### 3. Настройки

В `hub/.env` появляется по набору переменных на проект:

```
PANEL_ADDR=10.77.0.2:3001          # проект 1
RU_PROBER_ADDR=10.77.0.2:9115

PANEL_P2_ADDR=10.77.0.4:3001       # проект 2
P2_PROBER_ADDR=10.77.0.4:9115
PANEL_P2_API_URL=https://panel2.example.com
```

Секреты — отдельными файлами на проект: `hub/secrets/panel_p2_metrics_user`,
`panel_p2_metrics_password`, `panel_p2_api_token`.

### 4. Скрейпы

В `hub/vmagent/scrape.yml` каждый блок дублируется на проект, и во всех появляется
статический лейбл:

```yaml
  - job_name: remnawave_p2
    metrics_path: /metrics
    basic_auth:
      username_file: /etc/secrets/panel_p2_metrics_user
      password_file: /etc/secrets/panel_p2_metrics_password
    static_configs:
      - targets: ["%{PANEL_P2_ADDR}"]
        labels:
          project: p2
```

То же для `probe_nl_p2`, `probe_ru_p2`, `probe_ru_tcp_p2` — с `files:
[/etc/targets/nodes-p2.yml]` и `replacement: "%{P2_PROBER_ADDR}"`.

Проверка: имена нод в разных проектах могут совпадать. Лейбл `project` обязателен
везде, иначе метрики двух нод с именем `sech` склеятся в одну.

### 5. Список нод

`sync-nodes.sh` принимает проект аргументом и пишет свой файл:

```bash
./scripts/sync-nodes.sh p2     # → targets/nodes-p2.yml, порты из port-overrides-p2.conf
```

В cron — по строке на проект.

### 6. Правила

Во всех агрегациях `by(node)` заменяется на `by(project, node)`. Иначе ноды разных
проектов с одинаковыми именами будут перетирать друг друга в записанных метриках.

В аннотациях алертов добавить проект:

```yaml
      summary: "🔴 [{{ $labels.project }}] {{ $labels.node }} — сервер недоступен"
```

### 7. Маршруты алертов

Если у проектов разные дежурные — по чату на проект:

```yaml
  routes:
    - receiver: bot-p2
      matchers: ['project = "p2"']
```

Если дежурный один — оставить общий чат, проект виден в тексте.
Группировка становится `group_by: [alertname, project]`, чтобы авария одного проекта
не смешивалась в одно сообщение с аварией другого.

### 8. Бот

`/status` показывает сводку по проектам, детали — по кнопке или `/status p2`.
Переменная `TELEGRAM_CHAT_ID_P2` — если чаты разные.

## Порядок работ

Сначала целиком один новый проект — от WireGuard до первого алерта. На нём
вылезут все расхождения между панелями: разные версии, разные порты инбаундов,
разные схемы с CDN. Остальные два пойдут по накатанной.

Первый проект трогать в последнюю очередь: к нему сводится вся конфигурация,
и ломать работающее, пока не отлажено на новом, незачем.

## Чего делать не надо

Не поднимать второй хаб «чтобы не мешать первому». Один хаб на 100 нод четырёх
проектов — это те же 400 МБ памяти и тот же гигабайт истории в месяц.

Не разносить по разным телеграм-ботам без нужды: четыре бота в одном телефоне
различать в три часа ночи вы не будете.
